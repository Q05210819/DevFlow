# 第一阶段决策记录

按执行账本中 `Ruling:` 出现顺序保存。每项包含决定、原因及代价；后续裁决覆盖早期裁决时仍保留历史。这里记录已批准的工程取舍，不新增产品范围。源码和验收边界见 [阶段验收](foundation-acceptance.md)。

| 序号 | 决定 | 原因 | 代价或判断错误的影响 |

| 1 | 复用控制器已初始化的 Git 仓库及文档基线，不再创建嵌套仓库或工作树。 | 计划设置已经完成。 | 重复初始化会分裂历史。 |
| 2 | 共享模块按任务顺序实施。 | 审查门槛和 API 合同需要稳定基线。 | 增加等待时间；独立前端并行由后续裁决另行批准。 |
| 3 | 分页签名通过 Settings/签名密钥依赖注入，使用关键字参数或绑定 codec。 | 简写接口遗漏密钥来源，不能使用可变模块全局变量。 | 后续调用方须匹配调整后的接口。 |
